# Part 2: Differential Input Processing for Video Frames

Four consecutive 8-bit frames X0–X3 are processed on the 8x8 weight-stationary array with the
`features[27]` weights from Part 1:

- **Y0 = 16·(W×X0_hi) + (W×X0_lo)**: X0 is split into two 4-bit nibbles, 2 passes (unsigned activations)
- **Yi = Y0 + W×ΔXi**, ΔXi = Xi − X0 (signed 4-bit): 1 pass per frame (signed activations)
- Weights are loaded once per kernel position and kept for all passes: **5 passes instead of 8**

ΔXi is generated on the host side (Python). Nothing outside `part2/` was modified.

## Files

| Path | What it is |
|---|---|
| `data/X0.txt` … `X3.txt` | Provided input frames, `[8, 16, 16]`, unsigned 8-bit |
| `python/ref_model.py` | Bit-exact integer model of what the hardware computes (pass by pass, kij by kij) |
| `python/gen_files.py` | Writes the stimulus and expected outputs to `out/` (weights are read from Part 1's `hardware/weight_itile0_otile0_kij*.txt`) |
| `python/selftest.py` | Checks the model against PyTorch `conv2d` and decodes every generated file back |
| `hardware/verilog/` | Part 1 RTL + Part 2 changes (see below) |
| `hardware/sim/core_tb_part2.v` | Part 2 testbench, based on Part 1's `hardware/core_tb.v` |
| `hardware/sim/run_sim.sh` | Runs the Part 2 simulation (differential and/or conventional baseline) |
| `hardware/sim/run_part1_regression.sh` | Runs Part 1's original `core_tb.v` on the Part 2 RTL (`part1_cfg.v` sets the Part 1 width) |
| `hardware/sim/*.log` | Simulation results (see "Reading the results") |
| `out/summary.json` | Accuracy / saturation / bit-width statistics for the report |

`out/` (stimulus, golden, debug) is regenerated by `gen_files.py` and is not committed except `summary.json`.

## RTL changes (vs. Part 1 `hardware/verilog/`)

| File | Change |
|---|---|
| `mac.v` | New `mode` input: activation is zero-extended (`mode=0`, X0 nibbles) or sign-extended (`mode=1`, ΔX) |
| `mac_tile.v`, `mac_row.v`, `mac_array.v` | Pass `mode` down to every PE |
| `sfu.v` | Accumulator width `acc_bw` (24 bits, Y0 needs 19) and a `shift` input (adds `psum << 4` for the high-nibble pass) |
| `corelet.v` | `inst` widened to 43 bits; OFIFO psums are sign-extended to `acc_bw` before going to PMEM |
| `core.v` | Larger SRAMs: XMEM 32b × 4096, PMEM 192b × 32768 (via `sram_param.v`) |
| `sram_param.v` (new) | Parameterized SRAM, same interface and timing as `sram_*_w2048.v` |

New `inst` bits (all zero = Part 1 behaviour): `[36]` mode, `[37]` sfu_shift, `[38]` A_xmem[11], `[42:39]` A_pmem[14:11].

The SFU flow reuses Part 1's "first cycle of an acc burst loads" and `sfu_wb` store-back:
Y0 = one burst of 18 PMEM reads (9 high-nibble psums with `shift`, 9 low-nibble psums), stored back to PMEM;
Yi = one burst of 10 reads (the stored Y0 first, then 9 ΔXi psums), stored back.

## How to run

```bash
cd part2/python
python gen_files.py            # writes part2/out/
python selftest.py             # should print ALL PASS

cd ../hardware/sim
./run_sim.sh both              # differential + conventional, in parallel, about 5 minutes
./run_part1_regression.sh      # about 10 seconds
```

`./run_sim.sh diff` or `./run_sim.sh conv` runs only one of them; add `-DVCD` to dump waveforms (large).

## Reading the results

| Log | Content |
|---|---|
| `hardware/sim/diff.log` | Differential method (5 passes per weight set) |
| `hardware/sim/conv.log` | Conventional baseline (8 passes per weight set) |
| `hardware/sim/part1_regression.log` | Part 1 testbench on the Part 2 RTL |

Key lines of a passing Part 2 log (`diff.log`):

| Log line | Meaning |
|---|---|
| `psum check: all 14580 psum words matched` | Raw array outputs in PMEM (9 kij × 5 passes × 324 nij) match the Python reference |
| `sfp_out check: all 1024 outputs (y0..y3) matched` | SFU output after every output pixel (4 frames × 256) matches `out/golden/y*.txt` |
| `stored outputs in PMEM: all 1024 matched` | Y0..Y3 stored back to PMEM match the golden outputs |
| `RESULT passes=5 array=50868 sfu=15360 l1_write=1702 total=67946 errors=0` | Cycle summary (fields below) |
| `No error detected` | All checks passed |

`conv.log` has the same lines (its psum check covers 5832 words, only the X0 passes have Python dumps).

| `RESULT` field | Meaning |
|---|---|
| `passes` | Passes per weight set (5 differential, 8 conventional) |
| `array` | Cycles of kernel loading, XMEM→L0, execution and OFIFO→PMEM |
| `sfu` | Cycles of the SFU accumulation and store-back |
| `l1_write` | Cycles of DRAM→XMEM writes |
| `total` | All simulated cycles |
| `errors` | Total number of mismatches (0 = pass) |

### Current results

All checks pass with zero errors (differential, conventional and Part 1 regression).

| Cycles | Conventional (8 passes) | Differential (5 passes) | Speed-up |
|---|---|---|---|
| Array (load, XMEM→L0, execute, OFIFO→PMEM) | 81,162 | 50,868 | 1.60× |
| SFU (accumulate + store back) | 21,504 | 15,360 | 1.40× |
| Total without DRAM→XMEM | 102,682 | 66,244 | 1.55× |

ΔX is within [-7, 7] for all three frames, so no value saturates at 4 bits and Yi equals the full 8-bit
reference W×Xi exactly (see `out/summary.json`).
